# Release Notes - June 2026 Technical Updates & Tokenomics Revision

This release introduces a fully revised, sustainable tokenomics model with a 210M KRISTA supply cap, flat masternode collateral, quarterly (~90 days) block reward decay, and specific treasury allocations. Additionally, it integrates standard BLS12-381 signatures using the `supranational/blst` library, optimizes CPU mining performance by removing debug log spam, implements the dual-path non-masternode miner registration system, details network upgrade heights, and introduces official technical whitepapers.

---

## 1. Core Tokenomics & Emission Revision

We have refactored the emission schedule in [src/masternode.cpp](../src/masternode.cpp) and [src/chainparams.cpp](../src/chainparams.cpp) to implement a mathematically modeled, finite supply curve designed for long-term scarcity and security.

### Supply Cap & Decay Parameters
- **Maximum Supply (Hard Cap):** Defined as **210,000,000 KRISTA** in [src/chainparams.cpp](../src/chainparams.cpp) via `nMaxMoneyOut`.
- **Premine Block (Height 1):** Configured to yield **0 KRISTA** (Zero Premine) to ensure fair and organic network distribution.
- **Block 2+ Fixed Start & Period Decay (Heights 2+):** Emits **17 KRISTA** starting at Block 2 (Blocks 0–1 emit `0 KRISTA` on Mainnet, no graduated bootstrap tiers) and decays by **2.15%** every **~90 days (259,200 blocks)** from Block 2 (`(nHeight - 2) / 259200`) by multiplying the base reward by `0.9785` at each period boundary (`84,983 KRISTA` / `79,034.19 KRISTA` net by Block 5,000 for LLMQ/Model D formation).
- **Supply Asymptote:** Total circulation converges to **204,948,837 KRISTA** (`97.59%`), providing a **5.05M buffer (`2.41%`)** under the 210M hard cap to prevent sudden supply cutoffs.

### Masternode Collateral
- Updated to a flat, invariant **4,200 KRISTA** in `CMasternode::GetMasternodeNodeCollateral`. This establishes an optimal lock-up ratio while ensuring the network can easily scale to the 20+ active masternodes required for LLMQ quorum formation.

### Ecosystem Developer Treasury Split
Coinbase and coinstake transaction processing deducts funding allocations directly from block value before calculating reward distributions:
- **Developer Treasury (7%)**: Diverts 7% of block rewards to the Developer Fund Address (`KTeRC2Kj8hXcuzRohxPp2LtYFRJm2BceRoP`) starting at block height 2, leaving a uniform **93.0%** net reward pool across all emission phases.

### Block Reward Allocations & Model D
The remaining portion of each block reward is divided between masternodes and stakers/miners as follows:
- **Heights 2 to 199 (Classic PoW Bootstrap):** **100% Miner / 0% Masternode** to support initial distribution during node setup.
- **Heights 200 to 4,999 (Pre-Model D Cooperative ADAM):** Under `UPGRADE_FAIRNESS` (active from Block 1), **25% Block Producer (`20%` Staker + `5%` Signing Coordinator in PoS) / 75% Active ADAM Validators** (`IsAdamValidatorSplitActive`: equal `~6.818%` per solved seat across up to 11 committee seats, with unsolved shares split `50%` Automatic Protocol Burn + `50%` Developer Treasury). Legacy pre-Fairness rule was 60% Producer / 40% Validators (`8%/4%/2.857%`).
- **Heights 5001 to 100,000 (Early Stage):** **80% Masternode / 20% Miner-Staker** (overridden by Model D splits when active).
- **Heights 100,001+ (Maturation):** **60% Masternode / 40% Miner-Staker** (overridden by Model D splits when active).
- **Model D Consensus & `UPGRADE_FAIRNESS`**: Splits the net pool according to cooperative roles (Model D active starting at block 5,000 on Mainnet, block 500 on Testnet, block 200 on Regtest; Fairness active at Block 1):
  - **35% Passive Masternode Queue**
  - **10% Signer-Only LLMQ Quorum Validators** (paid 1-block lag strictly to members who co-signed the previous block's `vQuorumSig`, with `-5/+5` deterministic PoSe scoring)
  - **15% Block Proposer / Coordinator Symmetry** (`15% + tx fees` to Coordinator in PoW; **`12% + tx fees` to Staker + `3%` to Signing Coordinator** in PoS under `UPGRADE_FAIRNESS`)
  - **40% Equal-Work Validator Participants** (equal `40% / 11 ≈ 3.636%` per solved committee seat regardless of MN, Coin-Lock, or Open-PoW track)

## 2. Consensus & Protocol Enhancements

### Dynamic Puzzle Algorithms & Scaling (ADAM)
- **Uniform 17-Algo Mapping (`UPGRADE_FAIRNESS`):** Excludes asymmetric `HashX11KVS` (`algo 11`) from block-level ADAM puzzles so all committee seats solve uniform single-pass hashing algorithms: Fallback Mode (Version 11) selects `kUniformAlgos[Hash(Seed_H || MinerPubKey_i) % 17]` and Standard Mode (Version 12) compounds 3 distinct algorithms out of `17` (`4,080 = 17*16*15` permutations) alongside mandatory 33-byte compressed validator pubkeys. Legacy pre-Fairness used `18` algorithms / `4,896` permutations.
- **Difficulty Scaling Adjustments:** Solved a false-positive flood issue where miners submitted valid puzzles that did not meet the exact block target. The target difficulty for puzzle verification is scaled by shifting `bnTarget` by 6 bits (`nAdamDifficultyShiftV2 = 6` for blocks >= 5,000 on Mainnet, >= 500 on Testnet, >= 200 on Regtest) instead of the previous 10 bits (`nAdamDifficultyShiftV1 = 10`), stabilizing puzzle submission rate-limits.
- **Quorum Solution Threshold:** In `CreateNewBlock`, template generation is deferred if the available solutions cache fails to meet the effective consensus threshold (`GetAdamThreshold` / `GetAdamEffectiveThreshold`: `5` during bootstrap `< 50,000` on Mainnet, `< 100,000` on Testnet, `< 1,000` on Regtest; transitioning to `7` on Mainnet/Regtest and `3` on Testnet, with time-relaxed recovery down to `5` [`3` during sparse bootstrap] at $t \ge 120\text{s}$) rather than requiring a 100% submission rate, allowing block production to continue even if several elected miners are offline.
- **Version 12 Gating (`Consensus::UPGRADE_POMBL`):** Gated the transition from Fallback Mode (Version 11) to Standard PoMBL Mode (Version 12) deterministically by block height via `Consensus::UPGRADE_POMBL` (height `4,800` on Mainnet, `400` on Testnet, and `300` on Regtest), rejecting `nVersion < 12` blocks with `bad-version` once active while deferring dynamic BFT LLMQ `vQuorumSig` enforcement on Mainnet/Testnet until `Consensus::UPGRADE_MODELD` (`5,000` on Mainnet, `500` on Testnet).

### Integration of Supranational BLS (`blst`)
- Integrated the high-performance `supranational/blst` library for BLS12-381 signature generation and verification.
- Solved build issues related to static linking, assembly optimization flag compatibility, and test suite execution.

## 3. Non-Masternode Miner Registration System

- **Dual-Path Registration:** Implemented two distinct registration types for non-masternode nodes to participate in ADAM mining elections via `registerminer`:
  1. **Coin-Lock (`lock`):** Requires locking **250 KRISTA** (`MINER_REGISTRATION_LOCK_AMOUNT = 250 * COIN`, funded by inputs with $\ge 100$ confirmations, max `1` tx/block via `ADAM_MAX_COIN_LOCK_TX_PER_BLOCK = 1`, and max `1` active seat per wallet) collateral via CLTV timelocks for a minimum duration of **2,880 blocks** on Mainnet (`100 blocks` on Testnet/Regtest once Model D is active). Accepted at all block heights by consensus and manual `registerminer lock`, while background `AutoRegisterMiner` waits until height `>= 5,000` on Mainnet and thereafter auto-selects `Coin-Lock` only when renewing the wallet's own `Coin-Lock` seat or when the `1`-seat `Sub-Track 1B` quota is currently vacant (`< 1`) and `Track 2` holds at least `3` active `PoW-Lock` validators; outputs below 250 KRISTA are rejected in mempool (`bad-txns-coinlock-amount-too-small`) and ignored by `GetAdamMinerPool`.
  2. **PoW-Lock (`pow`):** Under `UPGRADE_HARDENING_V2` & `UPGRADE_FAIRNESS` (`nActivationHeight = 1`), both funded and unfunded `PoW-Lock` paths solve domain-separated 7-level recursive **`HashX11KVS`** CPU puzzles: Funded `PoW-Lock` (`"KRPL"`/`"POWLKv2"`) solves **`15` zero bits** on Mainnet (`13` on Testnet, `8` on Regtest) bound to an ancestor block within the last `100` blocks and locks **10 KRISTA** (`POW_LOCK_REGISTRATION_AMOUNT = 10 * COIN`, funded by inputs with $\ge 100$ confirmations, max `1` tx/block via `ADAM_MAX_POW_LOCK_TX_PER_BLOCK = 1`, and max `1` active seat per wallet) via CLTV timelock, while **0 KRISTA** (`Zero-Coin PoW`, `"KRZC"`/`"SYBILV2"`) solves **`15` zero bits** on Mainnet under `UPGRADE_FAIRNESS` (`12` Testnet, `8` Regtest) within a `10`-block on-chain challenge window, expiring after a `240`-block lease TTL (`50` blocks post-Model-D on Testnet/Regtest), capped at `MAX_ZEROCOIN_BOOTSTRAP_MINERS_FAIRNESS = 240` distinct keys (`16` legacy V2), and using proportional locked-capital Coordinator weights (`4,200 : 250 : 10` with `75%` MN floor via `ADAM_FAIR_COORD_V4`). Any funded `PoW-Lock` output below 10 KRISTA is rejected (`bad-txns-powlock-amount-too-small`).
- **Dual-Track ($7 + 1 + 3$) Committee Quotas (`nAdamDualTrackHeight`, block 200 on Mainnet/Testnet, block 1 on Regtest):** Partitioned the 11 validator seats into **Track 1 (8 Collateralized Seats: 7 Active Masternodes [`4,200 KRISTA`] + 1 strictly isolated Coin-Lock [`250 KRISTA`], enforced via `static_assert(ADAM_MASTERNODE_TRACK_QUOTA >= Consensus::Params::ADAM_MAX_CONSENSUS_THRESHOLD, ...)`)** and **Track 2 (3 Open PoW Seats)**, with strict empty-seat spillover order (`Active Masternodes -> Open PoW -> Coin-Lock last resort`), where every solved seat earns the exact equal `1/11` share (`40% / 11` Model D, `75% / 11` Pre-Model D) under `UPGRADE_FAIRNESS`.
- **Expiration Warning System:** Implemented automatic log warnings and GUI notifications when a miner's registration lock approaches expiration (`<= 240 blocks` / `~2 hours` remaining for `2,880`-block funded `Coin-Lock` and `10 KRISTA` `PoW-Lock` seats; `<= 24 blocks` / `~12 minutes` remaining for `240`-block `Zero-Coin PoW` bootstrap seats) to prevent sudden consensus dropouts.
- **Democratic Verification & Pool Scanning:** Nodes dynamically scan the UTXO database to construct the active miner pool and verify registration finality during block validations.

## 8. Consensus Finality, Masternode Isolation & Performance Hardening (`v1.4.5.9` – `v1.5.9.0`)

### Deterministic Equal-Work Fork Resolution
- **Lowest-Hash Tie-Breaker (`CBlockIndexWorkComparator` in [src/chain.h](../src/chain.h)):** When competing chain tips at the same height have equal cumulative chain work (`nChainWork`), nodes deterministically prefer the tip with the numerically smaller block hash (`pa->GetBlockHash() < pb->GetBlockHash()`) before checking local receipt sequence ID (`nSequenceId`), ensuring instantaneous (`< 1s`) network-wide convergence after partition recovery.

### LLMQ Anti-Equivocation & Multi-Hop Gossip Relay
- **Per-Parent Anti-Equivocation Guard (`llmq::AllowQuorumSignature` / `mapSignedProposalByPrev` in [src/llmq.cpp](../src/llmq.cpp)):** Quorum members track signed `(prevHash, coordinator, blockHash)` entries and enforce a `12s` same-coordinator cooldown and `QUORUM_EQUIVOCATION_GUARD_SECS = 30` cross-coordinator guard, preventing competing blocks on the same parent from both acquiring a dynamic BFT quorum certificate (`vQuorumSig`, `3-of-5` up to `8-of-15`).
- **Multi-Hop Gossip Relay (`setSeenProposedBlocks`, `mapQuorumBlockSigs` in [src/main.cpp](../src/main.cpp)):** Block proposals (`PROPOSEBLOCK` / `qblockprop`) and quorum signature shares (`QUORUMSIGSHARE` / `qsigshare`) are deduplicated and relayed across all connected peers.
- **100% On-Chain Fallback in `ElectQuorumMembers` ([src/llmq.cpp](../src/llmq.cpp)):** When on-chain active Masternode candidates (with unspent 4,200 KRISTA collateral and on-chain heartbeat pings within the last 2,880 blocks) are fewer than `nQuorumSize` (5), `ElectQuorumMembers` deterministically falls back to the on-chain `GetAdamMinerPool(nHeight - 1, pView)` pool without relying on in-memory `mnodeman`.

### Masternode Hot/Cold Isolation & Authenticated On-Chain Pings
- **Strict Hot/Cold Signing Isolation ([src/miner.cpp](../src/miner.cpp), [src/llmq.cpp](../src/llmq.cpp), [src/adam.cpp](../src/adam.cpp)):** Cold controller wallets (`masternode.conf`) only broadcast `CMasternodeBroadcast` activations and never sign LLMQ quorum shares, block proposals, or coordinator messages; only active Hot Nodes (`masternode=1` + `activemasternode.conf`) sign consensus messages.
- **Compressed & Uncompressed PubKey Support in `ExtractOnChainMasternodePing` ([src/adam.cpp](../src/adam.cpp)):** Supports both 33-byte compressed (`36-byte` `<pubkey> OP_CHECKSIGVERIFY OP_1` script) and 65-byte uncompressed (`68-byte` script generated by `createmasternodekey`) Masternode public keys alongside the `CDataStream` `OP_RETURN` proof (`collateralOutpoint` + `vchPingSig` + optional `COnChainMasternodeDelegation`).
- **On-Chain Ping Fee Exemption (`0.0001 KRISTA` in [src/main.cpp](../src/main.cpp) & [src/masternode.cpp](../src/masternode.cpp)):** Authenticated on-chain Masternode ping transactions (`0.01 KRISTA` self-spendable UTXO broadcast after $\ge 1,440$ idle blocks) are exempt from the `1000x` `OP_RETURN` relay fee multiplier in `GetMinRelayFee` (subject to strict `<= 850`-byte / `400`-byte `OP_RETURN` zero-trailing-byte format, Taproot `control_block` + UTXO verification, unconditional `vchPingSig`, 1-pending-per-MN mempool uniqueness, and a `360`-block per-MN cooldown), paying a flat `0.0001 KRISTA` fee while regular block participation renews status at zero fee.

### Lock-Free Chain Tip Access & Peer Discovery Infrastructure
- **Lock-Free `CChain::AtomicTip()` ([src/chain.h](../src/chain.h), [src/chain.cpp](../src/chain.cpp), [src/main.cpp](../src/main.cpp)):** Added an atomic tip pointer (`std::atomic<CBlockIndex*> pAtomicTip`) updated in `CChain::SetTip()`, enabling `GetChainTip()` to read the active tip without acquiring `cs_main`.
- **Fixed Seeds & Live DNS Seeder ([src/chainparamsseeds.h](../src/chainparamsseeds.h)):** Populated `pnSeed6_main` and `pnSeed6_test` with the 4 seed node IPv4-mapped IPv6 addresses and deployed the live DNS Seeder at `seeder.kristalteknoloji.com`.

### Standby Validator Handover, Time-Relaxed Quorum & Incentive Alignment (`Rev 30–35`)
- **Dual-Track ($7 + 1 + 3$) Masternode Quorum Guarantee ([src/adam.h](../src/adam.h), [src/adam.cpp](../src/adam.cpp), [src/chainparams.cpp](../src/chainparams.cpp)):** Set `ADAM_MASTERNODE_TRACK_QUOTA = 7` and `ADAM_COIN_LOCK_TRACK_QUOTA = 1` within `ADAM_COLLATERALIZED_TRACK_QUOTA = 8` alongside `ADAM_OPEN_POW_TRACK_QUOTA = 3`, enforced via compile-time `static_assert` and runtime `assert(ADAM_MASTERNODE_TRACK_QUOTA >= consensus.nAdamThreshold)` so Active Masternodes alone always meet the post-bootstrap quorum threshold (`7`).
