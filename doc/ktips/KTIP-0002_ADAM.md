## Abstract
This proposal introduces the **ADAM (A Decentralized Approach Model)** cooperative consensus mechanism. ADAM splits block validation and creation into three distinct cooperative phases: leader election, lightweight puzzle solving, and block signature aggregation. It prevents mining pool centralization, selfishness, and leader DoS attacks by requiring cooperative work from multiple elected nodes (11 miners and 1 coordinator) to validate each block.

## Motivation
Traditional Proof-of-Work (PoW) protocols suffer from pool centralization, where a few entities dominate block generation. They are also vulnerable to selfish mining and targeted Denial-of-Service (DoS) attacks on block producers whose identity is predictable. Standard Proof-of-Stake (PoS) protocols suffer from "nothing-at-stake" forks. 

ADAM resolves these vulnerabilities by forcing a group of validator nodes to collaborate:
* The identity of the block producer (the Coordinator) is hidden and unpredictable until block generation.
* The block hash depends on the sequential cryptographic work of multiple independent miners, neutralizing selfish mining.
* Masternodes provide the baseline election pool, preventing Sybil attacks.

## Specification

### 1. Deterministic Leader Election (SSLE)
At each block height $H$, the active validator pool (masternodes and registered miners) is queried. The network utilizes a Single Secret Leader Election (SSLE) protocol to select $N = 11$ Miners and $1$ Coordinator based on a rolling random seed:

$$\text{Seed}_H = \text{Hash}\left(\text{Seed}_{H-1} \mathbin{\Vert} \text{VRFProof}_{H-1}\right)$$

Where $\text{VRFProof}_{H-1}$ is the deterministic hybrid signature generated by the Coordinator of block $H-1$.

Every node $i$ in the active pool is ranked:

$$\text{Rank}_i = \text{Hash}\left(\text{Seed}_H \mathbin{\Vert} \text{PubKey}_i\right)$$

The pool is sorted in ascending order of their rank. When `nHeight >= consensus.nAdamDualTrackHeight` (block `200` on Mainnet/Testnet matching `UPGRADE_ADAM`, block `1` on Regtest), the $N = 11$ Miners are elected via **Dual-Track Quota Election (`ElectDualTrackValidators`)**:
* **Track 1 (Collateralized Pool — 8 Seats)**: **7 seats** for Active Masternodes (`4,200 KRISTA`, enforced via `static_assert(ADAM_MASTERNODE_TRACK_QUOTA >= 7)`) and **1 strictly isolated seat** for Coin-Lock miners (`250 KRISTA`) (vacant Coin-Lock seat spills over to Active Masternodes).
* **Track 2 (Open PoW Pool — 3 Seats)**: **3 seats** for Open PoW miners in strict tier priority (`Tier 2A`: `10 KRISTA` Funded PoW-Locks $\rightarrow$ `Tier 2B`: Bootstrap $\rightarrow$ `Tier 2C`: `0 KRISTA` Zero-Coin PoW). Unselected `Coin-Lock` registrations are strictly excluded from `Tier 2A` and serve only as last-resort liveness fallback if fewer than 10 non-Coin-Lock candidates remain. Vacant seats spill over in order: **Active Masternode $\to$ Open PoW $\to$ Coin-Lock (last resort, earning `~2.857%` MN seat base)**.
Under `UPGRADE_HARDENING_V2`, the primary Coordinator is elected across all funded validators via quota-capped quadratic stake-weighted VRF (**Active Masternodes = `65`** each [$\text{round}(\sqrt{4200})$], at most 1 VRF-top **Coin-Lock = `16`** [$\text{round}(\sqrt{250})$], and at most 3 VRF-top **Funded PoW-Locks = `4`** each [$\lceil\sqrt{10}\rceil$, `12` track cap]; falling back to `Bootstrap -> Zero-Coin PoW` only when no funded validators exist).

### 2. Lightweight PoW Puzzle Solving
Elected miners must prove they performed work by solving a lightweight cryptographic puzzle. The difficulty target is relaxed using a bit-shift multiplier:

$$\text{scaledTarget} = \text{Target} \ll \text{activeShift}$$

The shift value is height-dependent (`NetworkUpgradeActive(nHeight, Consensus::UPGRADE_ADAM_V2)`):
* $\text{activeShift} = \text{nAdamDifficultyShiftV1} = 10$ before `Consensus::UPGRADE_ADAM_V2` (block `705` on Mainnet/Regtest, block `300` on Testnet).
* $\text{activeShift} = \text{nAdamDifficultyShiftV2} = 6$ at or above `Consensus::UPGRADE_ADAM_V2` (block `705` on Mainnet/Regtest, block `300` on Testnet).

Miners solve the following target equation:

$$\text{PuzzleHash}_i \le \text{scaledTarget}$$

In Fallback Mode (Block Version 11, prior to `Consensus::UPGRADE_POMBL`), $\text{PuzzleHash}_i$ uses a single deterministically selected algorithm $\text{algo}_i = \text{GetAdamPuzzleAlgo}(\text{Seed}_H, \text{MinerPubKey}_i)$ out of 18 energy-efficient hash functions. Starting at `Consensus::UPGRADE_POMBL` (Block Version 12), $\text{PuzzleHash}_i$ is computed using a 3-permutation selector scheme (`GetAdam3PermutationAlgos`):

$$\text{PuzzleHash}_i = \text{algo1}\left( (i + 1) \times \text{algo2}\left( (i + 1) \times \text{algo3}(\text{Challenge}) \right) \right) \pmod{2^{256}}$$

And the serialized challenge stream (`CDataStream`) is defined as:

$$\text{Challenge} = \text{Seed}_H \mathbin{\Vert} \text{CompactSize}(\text{MinerPubKey}_i) \mathbin{\Vert} \text{MinerPubKey}_i \mathbin{\Vert} \text{LE32}(\text{Nonce}_i)$$

### 3. Block Hashing Chain (Stateless Hashing)
To bind the block header cryptographically to the work of all elected miners, the block hash ($H_{\text{block}}$) is computed by sequentially chaining the hashing operations of all elected miners.

For a serialized block header $S$:
1. For each round $i \in \lbrace 0, \dots, M-1 \rbrace$ (where $M$ is the number of miners), we calculate an odd coprime multiplier $m_i$ to preserve hash entropy:

   $$\text{roundHash}_i = \text{Hash}\left(\text{hashPrevBlock} \mathbin{\Vert} i\right)$$

   $$m_i = \max\left(\text{roundHash}_i[0] \mid 1, 3\right)$$

2. The rounds are chained sequentially:
   - **Round 0**:
     * Derive $\text{algo1}$, $\text{algo2}$, and $\text{algo3}$ for miner $0$.
     * Compute:

       $$H_0^{(3)} = \text{CalculateAdamPuzzleHash}(\text{algo3}, S)$$

       $$H_0^{(2)} = \text{CalculateAdamPuzzleHash}\left(\text{algo2}, \left( H_0^{(3)} \times 1 \right) \pmod{2^{256}}\right)$$

       $$H_0 = \text{CalculateAdamPuzzleHash}\left(\text{algo1}, \left( H_0^{(2)} \times 1 \right) \pmod{2^{256}}\right)$$

     * Apply multiplier:

       $$H_{\text{prev}} = (H_0 \times m_0) \pmod{2^{256}}$$

   - **Round $i > 0$**:
     * Derive $\text{algo1}$, $\text{algo2}$, and $\text{algo3}$ for miner $i$.
     * Compute:

       $$H_i^{(3)} = \text{CalculateAdamPuzzleHash}(\text{algo3}, H_{\text{prev}})$$

       $$H_i^{(2)} = \text{CalculateAdamPuzzleHash}\left(\text{algo2}, \left( H_i^{(3)} \times (i + 1) \right) \pmod{2^{256}}\right)$$

       $$H_i = \text{CalculateAdamPuzzleHash}\left(\text{algo1}, \left( H_i^{(2)} \times (i + 1) \right) \pmod{2^{256}}\right)$$

     * Apply multiplier:

       $$H_{\text{prev}} = (H_i \times m_i) \pmod{2^{256}}$$

3. The final output is the block hash:

   $$H_{\text{block}} = H_{\text{prev}}$$

### 4. Quorum-Resilient Responding, Standby Handover & Time-Relaxed Threshold
To prevent offline or lagging miners from freezing block production, block templates can be generated and propagated if a minimum quorum threshold ($T = \text{GetAdamThreshold}(nHeight)$) of solutions is received:
* **Bootstrap Phase (`nHeight < nAdamThresholdBootstrapLimit`, i.e., 50,000 on Mainnet, 100,000 on Testnet, 1,000 on Regtest)**: $T = 5$ out of $11$ miners.
* **Post-Bootstrap (`nHeight >= nAdamThresholdBootstrapLimit`)**: $T = 7$ out of $11$ miners on Mainnet / Regtest (`3` on Testnet).
* **Standby Validator Seat Handover ($t \ge 60\text{s}$)**: If primary seats remain silent at `nTimeElapsed >= 60s` (`ADAM_COMMITTEE_FALLBACK_TIMEOUT_SECS = 60`), `ResolveAdamCommitteeForTime` / `ValidateAdamCommitteeForTime` allow the active Coordinator to replace unsolved primary seats strictly with same-track standby candidates (`MN -> MN`, `Coin-Lock -> Coin-Lock`, `Open PoW -> Open PoW`) in sequential rank order verified against the block's `CCoinsViewCache* pView`.
* **Time-Relaxed Quorum Threshold ($t \ge 120\text{s}$)**: If the committee still cannot reach the baseline threshold $T$, `GetAdamEffectiveThreshold(nHeight, nTimeElapsed, nActiveMasternodes)` relaxes the threshold by `1` every `60s` starting at $t = 120\text{s}$ down to `ADAM_MIN_RELAXED_THRESHOLD = 5` (`> 4` non-MN seats, ensuring at least 1 Active Masternode is always required when post-bootstrap OR active MNs $\ge 7$, or `ADAM_MIN_RELAXED_THRESHOLD_BOOTSTRAP = 3` during early bootstrap when active MNs $< 7$).
* **Fallback Coordinator Rotation ($t \ge 45\text{s}$)**: If the primary Coordinator does not publish a block within `45 seconds` (`ADAM_FALLBACK_COORDINATOR_TIMEOUT_SECS = 45`), `GetAdamFallbackCoordinatorForSlot` rotates block-proposing authority across 30-second fallback slots among the 11 elected validators ordered by PoBLS XOR distance (`RankValidatorsByPoBLSDistance`).

If an elected miner's solution is missing but the quorum threshold is met, the Coordinator substitutes the missing miner's solution with an empty vector placeholder:

$$
\text{vAdamSolutions}[i] = \text{std::vector}{<}\text{unsigned char}{>}\text{()}
$$

This maintains the 1:1 positional alignment between miners and solutions inside the block header. Empty placeholders are treated as invalid/skipped solutions during block validation, do not count toward the quorum verification check, and receive **0%** of the `40%` Participant Validator reward (active from block `200` under `IsAdamValidatorSplitActive` and continuing under Model D; their unclaimed per-seat track share [`~2.857%` MN / `8.00%` Coin-Lock / `4.00%` Open PoW] is split **50% to the Automatic Protocol Burn** and **50% to the Developer Treasury**).

## Backward Compatibility
ADAM is activated conditionally based on block height:
* Activated on Testnet/Regtest/Mainnet at block height `200`.
* Fallback Mode (Block Version 11) runs during the bootstrap phase where the network lack masternodes.
* Standard Mode (Block Version 12) enforces the full masternode election loop and is deterministically activated via `Consensus::UPGRADE_POMBL` at block height `2000` (Mainnet), `400` (Testnet), or `300` (Regtest).
