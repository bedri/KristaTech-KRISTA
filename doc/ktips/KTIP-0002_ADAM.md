## Abstract
This proposal introduces the **ADAM (A Decentralized Approach Model)** cooperative consensus mechanism. ADAM splits block validation and creation into three distinct cooperative phases: leader election, lightweight puzzle solving, and block signature aggregation. It prevents mining pool centralization, selfishness, and leader DoS attacks by requiring cooperative work from multiple elected nodes (`15` miners under Balanced Model D [`11` Pre-Model D] and `1` coordinator) to validate each block.

## Motivation
Traditional Proof-of-Work (PoW) protocols suffer from pool centralization, where a few entities dominate block generation. They are also vulnerable to selfish mining and targeted Denial-of-Service (DoS) attacks on block producers whose identity is predictable. Standard Proof-of-Stake (PoS) protocols suffer from "nothing-at-stake" forks. 

ADAM resolves these vulnerabilities by forcing a group of validator nodes to collaborate:
* The identity of the block producer (the Coordinator) is hidden and unpredictable until block generation.
* The block hash depends on the sequential cryptographic work of multiple independent miners, neutralizing selfish mining.
* Masternodes provide the baseline election pool, preventing Sybil attacks.

## Specification

### 1. Deterministic Leader Election (SSLE)
At each block height $H$, the active validator pool (masternodes and registered miners) is queried. The network utilizes a Single Secret Leader Election (SSLE) protocol to select $N = 15$ Miners under Balanced Model D ($N = 11$ Pre-Model D) and $1$ Coordinator based on a rolling random seed:

$$\text{Seed}_H = \text{Hash}\left(\text{Seed}_{H-1} \mathbin{\Vert} \text{VRFProof}_{H-1}\right)$$

Where $\text{VRFProof}_{H-1}$ is the deterministic hybrid signature generated by the Coordinator of block $H-1$.

Every node $i$ in the active pool is ranked:

$$\text{Rank}_i = \text{Hash}\left(\text{Seed}_H \mathbin{\Vert} \text{PubKey}_i\right)$$

The pool is sorted in ascending order of their rank. When `nHeight >= consensus.nAdamDualTrackHeight` (block `200` on Mainnet/Testnet matching `UPGRADE_ADAM`, block `1` on Regtest), the $N$ Miners ($11$ Pre-Model D; expanded to $15$ upon `UPGRADE_MODELD` at block `5,000` on Mainnet, `500` on Testnet, `200` on Regtest) are elected via **Dual-Track Quota Election (`ElectDualTrackValidators`)**:
* **Track 1 (Collateralized Pool — `10` Seats under Model D / `8` Pre-Model D)**: **8 seats** for Active Masternodes (`4,200 KRISTA`; `7` seats Pre-Model D, enforced via `static_assert(ADAM_MODELD_MASTERNODE_TRACK_QUOTA >= 8)` and `ADAM_MASTERNODE_TRACK_QUOTA >= 7`) and **2 strictly isolated seats** for Coin-Lock miners (`250 KRISTA`; `1` seat Pre-Model D) (vacant Coin-Lock seats spill over to Active Masternodes).
* **Track 2 (Open PoW Pool — `5` Seats under Model D / `3` Pre-Model D)**: Once `nHeight >= consensus.nAdamOpenEntryHeight` (block `2,500` on Mainnet, block `1` on Testnet/Regtest), allocates **3 seats** under Model D (**2 seats** Pre-Model D) for Funded PoW-Locks (`10 KRISTA`, spilling to Active MN / Bootstrap if vacant) and **2 permanently open seats** under Model D (**1 seat** Pre-Model D) for `0 KRISTA` Open-Entry (`Tier 2C`, expanded under `UPGRADE_FAIRNESS` at Block `1` to `240` keys at `15`-bit Mainnet `HashX11KVS` PoW, spilling to Funded PoW-Lock / Bootstrap if vacant). Under `UPGRADE_HARDENING_V4` (`"Hardening_v4"`, Height `1` across Mainnet/Testnet/Regtest), all Coin-Lock, Funded PoW-Lock, and Zero-Coin registration scripts prepend mandatory `<blsPubKey(48B)> <blsPoP(96B)> OP_2DROP` (`bad-txns-minerreg-missing-bls`, `bad-txns-minerreg-bls-pop`, `bad-txns-minerreg-dup-bls`), binding PoW preimages via `Hash(challenge || blsPubKey)` with V4 suffixes `"POWLKv4"` / `"SYBILV4"` and binding `VerifyAdamOrDip3Signature` to the pinned BLS key. Unselected `Coin-Lock` registrations are strictly excluded from `Tier 2A` and serve only as last-resort liveness fallback if fewer than 13 non-Coin-Lock candidates remain under Model D (`< 10` Pre-Model D). Vacant seats spill over in order: **Active Masternode $\to$ Open PoW $\to$ Coin-Lock (last resort)** — and under `UPGRADE_FAIRNESS`, every solved seat earns the **exact same equal share** regardless of track.
Under `UPGRADE_HARDENING_V2` & `UPGRADE_FAIRNESS` (`nActivationHeight = 1`), `SelectAdamNodes` elects the primary Coordinator across funded validators via **Proportional Locked-Capital VRF (`4,200` per Active MN, `250` per `Coin-Lock`, and `10` per `Funded PoW-Lock`, with no per-track representative caps; enforcing an exact `>= 75%` Active MN security floor under `ADAM_FAIR_COORD_V4` when `3 * sumNonMN > sumMN` Pre-Model D, and transitioning to an exact `>= 55%` Active MN security floor under `ADAM_FAIR_COORD_V5` when `11 * sumNonMN > 9 * sumMN` once `UPGRADE_MODELD` is active; replacing legacy `65:8:2`)**, falling back to `Bootstrap -> Zero-Coin PoW` only when no funded validators exist. Under `UPGRADE_HARDENING_V4` (Height `1`), `SelectAdamNodes` enforces `ADAM_VRF_KEY_MATURITY = 100` blocks by prioritizing funded validator keys matured for at least `100` blocks (`totalMaturedWeight > 0`, falling back to unmatured keys only when no matured keys exist), preventing fresh-key VRF grinding.

### 2. Lightweight PoW Puzzle Solving
Elected miners must prove they performed work by solving a lightweight cryptographic puzzle. The difficulty target is relaxed using a bit-shift multiplier:

$$\text{scaledTarget} = \text{Target} \ll \text{activeShift}$$

The shift value is height-dependent (`NetworkUpgradeActive(nHeight, Consensus::UPGRADE_ADAM_V2)`):
* $\text{activeShift} = \text{nAdamDifficultyShiftV1} = 10$ before `Consensus::UPGRADE_ADAM_V2` (block `5,000` on Mainnet, block `500` on Testnet, block `200` on Regtest).
* $\text{activeShift} = \text{nAdamDifficultyShiftV2} = 6$ at or above `Consensus::UPGRADE_ADAM_V2` (block `5,000` on Mainnet, block `500` on Testnet, block `200` on Regtest).

Miners solve the following target equation:

$$\text{PuzzleHash}_i \le \text{scaledTarget}$$

In Fallback Mode (Block Version 11, prior to `Consensus::UPGRADE_POMBL`), $\text{PuzzleHash}_i$ uses a single deterministically selected algorithm $\text{algo}_i = \text{GetAdamPuzzleAlgo}(\text{Seed}_H, \text{MinerPubKey}_i)$ out of the uniform `17` single-pass hashing algorithms (`kUniformAlgos`, excluding asymmetric `X11KVS` `algo 11` under `UPGRADE_FAIRNESS` from Block `1`; legacy `18`). Starting at `Consensus::UPGRADE_POMBL` (Block Version 12), $\text{PuzzleHash}_i$ is computed using a 3-permutation selector scheme (`GetAdam3PermutationAlgos`: `4,080` uniform permutations with mandatory 33-byte compressed validator pubkeys):

$$\text{PuzzleHash}_i = \text{algo1}\left( (i + 1) \times \text{algo2}\left( (i + 1) \times \text{algo3}(\text{Challenge}) \right) \right) \pmod{2^{256}}$$

And the serialized challenge stream (`CDataStream`) is defined as:

$$\text{Challenge} = \text{Seed}_H \mathbin{\Vert} \text{CompactSize}(\text{MinerPubKey}_i) \mathbin{\Vert} \text{MinerPubKey}_i \mathbin{\Vert} \text{LE32}(\text{Nonce}_i)$$

### 3. Block Hashing Chain (Stateless Hashing)
To bind the block header cryptographically to the work of all elected miners, the block hash ($H_{\text{block}}$) is computed by sequentially chaining the hashing operations of all elected miners. In `CBlockHeader::GetHash()` (`src/primitives/block.cpp`), `fFallbackMode = (nVersion == 11) || (vAdamMiners.size() == vAdamSolutions.size() + 1)` — so Version 11 (or legacy fallback headers carrying a trailing Coordinator key) hashes $M = \text{vAdamMiners.size()} - 1$ miner rounds, whereas Version 12 headers with equal-length vectors hash all $M = \text{vAdamMiners.size()}$ committee seats in 3-permutation mode ($M = 15$ under Model D, $M = 11$ Pre-Model D).

For a serialized block header $S$:
1. For each round $i \in \lbrace 0, \dots, M-1 \rbrace$ (where $M$ is the number of miners), we calculate an odd coprime multiplier $m_i$ to preserve hash entropy:

   $$\text{roundHash}_i = \text{Hash}\left(\text{hashPrevBlock} \mathbin{\Vert} i\right)$$

   $$m_i = \max\left(\text{roundHash}_i[0] \mid 1, 3\right)$$

2. The rounds are chained sequentially:
   - **Round 0**:
     * Derive $\text{algo1}$, $\text{algo2}$, and $\text{algo3}$ for miner $0$.
     * Compute:

       $$H_0^{(3)} = \text{CalculateAdamPuzzleHash}(\text{algo3}, S)$$

       $$H_0^{(2)} = \text{CalculateAdamPuzzleHash}\left(\text{algo2}, \left( H_0^{(3)} \times 1 \right) \pmod{2^{256}}\right)$$

       $$H_0 = \text{CalculateAdamPuzzleHash}\left(\text{algo1}, \left( H_0^{(2)} \times 1 \right) \pmod{2^{256}}\right)$$

     * Apply multiplier:

       $$H_{\text{prev}} = (H_0 \times m_0) \pmod{2^{256}}$$

   - **Round $i > 0$**:
     * Derive $\text{algo1}$, $\text{algo2}$, and $\text{algo3}$ for miner $i$.
     * Compute:

       $$H_i^{(3)} = \text{CalculateAdamPuzzleHash}(\text{algo3}, H_{\text{prev}})$$

       $$H_i^{(2)} = \text{CalculateAdamPuzzleHash}\left(\text{algo2}, \left( H_i^{(3)} \times (i + 1) \right) \pmod{2^{256}}\right)$$

       $$H_i = \text{CalculateAdamPuzzleHash}\left(\text{algo1}, \left( H_i^{(2)} \times (i + 1) \right) \pmod{2^{256}}\right)$$

     * Apply multiplier:

       $$H_{\text{prev}} = (H_i \times m_i) \pmod{2^{256}}$$

3. The final output is the block hash:

   $$H_{\text{block}} = H_{\text{prev}}$$

### 4. Quorum-Resilient Responding, Standby Handover & Time-Relaxed Threshold
To prevent offline or lagging miners from freezing block production, block templates can be generated and propagated if a minimum quorum threshold ($T = \text{GetAdamThreshold}(nHeight, nActiveMasternodes)$) of solutions is received:
* **Bootstrap Phase (`nHeight < nAdamThresholdBootstrapLimit`, i.e., 50,000 on Mainnet, 100,000 on Testnet, 1,000 on Regtest)**: Under Model D + `UPGRADE_HARDENING_V4` (Height `1`), `GetAdamThreshold(nHeight, nActiveMasternodes)` enforces **$T = 8$** (`> 7` non-MN seats) immediately during bootstrap on Mainnet / Regtest once `nActiveMasternodes >= 8` (falling back to $T = 5$ only while active Masternodes `< 8`, or $T = 3$ on Testnet where `nAdamThresholdModelD = 3`; Pre-Model D $T = 5$ out of $11$; Pre-V4 historical bootstrap threshold was $5$ regardless of active Masternode count).
* **Post-Bootstrap (`nHeight >= nAdamThresholdBootstrapLimit`)**: $T = 8$ out of $15$ miners under Model D on Mainnet / Regtest (`ADAM_MODELD_MAX_CONSENSUS_THRESHOLD = 8`; Pre-Model D $T = 7$ out of $11$; `3` on Testnet).
* **Standby Validator Seat Handover ($t \ge 60\text{s}$)**: If primary seats remain silent at `nTimeElapsed >= 60s` (`ADAM_COMMITTEE_FALLBACK_TIMEOUT_SECS = 60`), `ResolveAdamCommitteeForTime` / `ValidateAdamCommitteeForTime` allow the active Coordinator to replace unsolved primary seats strictly with same-track standby candidates (`MN -> MN`, `Coin-Lock -> Coin-Lock`, `Open PoW -> Open PoW`) in sequential rank order verified against the block's `CCoinsViewCache* pView`.
* **Time-Relaxed Quorum Threshold ($t \ge 120\text{s}$)**: If the committee still cannot reach the baseline threshold $T$, `GetAdamEffectiveThreshold(nHeight, nTimeElapsed, nActiveMasternodes)` relaxes the threshold by `1` every `60s` starting at $t = 120\text{s}$ down to **`ADAM_MODELD_MIN_RELAXED_THRESHOLD = 8`** under Model D (`> 7` non-MN seats [`2 Coin-Lock + 5 Open PoW`], ensuring at least 1 Active Masternode is always required when post-bootstrap OR active MNs $\ge 8$; under Model D + V4, `baseThreshold` already starts at `8` once `nActiveMasternodes >= 8`), or `ADAM_MIN_RELAXED_THRESHOLD = 5` Pre-Model D (`> 4` non-MN seats when post-bootstrap OR active MNs $\ge 7$), or `ADAM_MIN_RELAXED_THRESHOLD_BOOTSTRAP = 3` during early bootstrap when active MNs $< 8$ under Model D (`< 7` Pre-Model D).
* **Fallback Coordinator Rotation ($t \ge 45\text{s}$)**: If the primary Coordinator does not publish a block within `45 seconds` (`ADAM_FALLBACK_COORDINATOR_TIMEOUT_SECS = 45`), `GetAdamFallbackCoordinatorForSlot` rotates block-proposing authority across 30-second fallback slots among the `15` elected validators under Model D (`11` Pre-Model D) ordered by PoBLS XOR distance (`RankValidatorsByPoBLSDistance`, which under `UPGRADE_HARDENING_V4` prioritizes keys matured for `ADAM_VRF_KEY_MATURITY = 100` blocks ahead of newer keys).

If an elected miner's solution is missing but the quorum threshold is met, the Coordinator substitutes the missing miner's solution with an empty vector placeholder:

$$
\text{vAdamSolutions}[i] = \text{std::vector}{<}\text{unsigned char}{>}\text{()}
$$

This maintains the 1:1 positional alignment between miners and solutions inside the block header. Empty placeholders are treated as invalid/skipped solutions during block validation, do not count toward the quorum verification check, and receive **0%** of the Active Validator reward (active from block `200` under `IsAdamValidatorSplitActive`: under `UPGRADE_FAIRNESS`, **`60% / 15 = 4.00%`** per solved seat under Model D [`0.6324 KRISTA` in Period 0 with `0` satoshi remainder when `15/15` solve] and `75% / 11 ≈ 6.818%` per solved seat Pre-Model D equally regardless of track; any remainder is paid only when all `15/15` seats solve under Model D [`11/11` Pre-Model D], and unclaimed shares are split **50% to the Automatic Protocol Burn** and **50% to the Developer Treasury**).

## Backward Compatibility
ADAM is activated conditionally based on block height:
* Activated on Testnet/Regtest/Mainnet at block height `200`.
* Fallback Mode (Block Version 11) runs during the bootstrap phase where the network lack masternodes.
* Standard Mode (Block Version 12) enforces the full masternode election loop and is deterministically activated via `Consensus::UPGRADE_POMBL` at block height `4800` (Mainnet), `400` (Testnet), or `300` (Regtest), while Balanced Model D (`Consensus::UPGRADE_MODELD`) expands the committee to `15` seats (`8 + 2 + 5`) at block `5,000` (Mainnet), `500` (Testnet), or `200` (Regtest), and `Consensus::UPGRADE_HARDENING_V4` (`"Hardening_v4"`) activates at height `1` across Mainnet, Testnet, and Regtest.
